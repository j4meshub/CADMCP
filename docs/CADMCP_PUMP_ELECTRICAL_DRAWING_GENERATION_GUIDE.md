# 使用 CADMCP 批量生成泵控制、电气接线与 PLC 图纸的技术方法

## 1. 文档目的

本文总结一次真实 AutoCAD 电气图纸补全任务的执行方法，供其他大模型或自动化代理学习。任务的核心不是简单复制图元，而是：

1. 从用户预选的两排图纸中识别供油泵和卸油泵母版；
2. 理解元件编号、线号、PLC 信号及控制连接规则；
3. 在指定方向和空白区域生成 2#、3#泵控制原理图；
4. 生成对应的外部接线图、端子排图和 PLC 接线图；
5. 校核编号、触点、导线拓扑和跨图信号关系。

本文重点介绍如何借助 `cadmcp-local` 的 `send_code_to_cad`，在 AutoCAD 进程内执行动态 C#，完成可靠的分析、复制、变换、改号与验证。

---

## 2. 如何理解用户命令

### 2.1 先把自然语言转换成结构化任务

用户命令中包含以下约束：

| 维度 | 第一排 | 第二排 | 第三排 |
|---|---|---|---|
| 母版 | 1#供油泵控制原理图 | 1#卸油泵控制原理图 | 无直接母版 |
| 生成内容 | 2#、3#供油泵控制图，随后生成供油泵外接/端子图 | 2#、3#卸油泵控制图，随后生成卸油泵外接/端子图 | PLC接线图（二）、（三） |
| 布局 | 在母版右侧连续排列 | 在母版右侧连续排列 | 在第三排左对齐排列 |
| 保持不变 | 图层、文字样式、线型、图框样式、横向间距 | 同左 | 参考既有AC柜接线图样式 |
| 需要变化 | 泵编号、元件编号、线号、特殊电机/按钮盒号、图名、图号 | 同左 | 图名、图号、页码及摆放位置 |

执行时把用户句子中的一次口误——“根据生成后的三台卸油泵控制原理图”——按上下文解释为第一排“三台供油泵”。判断依据是该句前后都在描述第一排供油泵，而第二排才单独描述卸油泵。

### 2.2 不采用“看到数字1就替换”的策略

电气图中的数字可能属于不同语义：

- 泵序号；
- 元件编号；
- 原理线号；
- 柜号，如 AP1、AP2；
- PLC 模块或通道号；
- 图号、页码、日期；
- 电压或设备参数；
- 说明文字中的示例。

因此，编号修改必须基于“编号类别”，不能使用全局字符串替换。正确策略是先建立规则表，再对满足完整格式的文本执行替换。

### 2.3 执行前的必要前置检查

即使用户要求直接执行，也应先做只读检查：

1. 当前预选集是否存在；
2. 预选集中是否能识别出两排控制图；
3. 图框插入点、横向步距、行距是否可确定；
4. 目标区域是否为空；
5. 母版实体数是否符合预期。

如果预选集为 0，就不能安全猜测用户希望使用哪两排图，应重新读取或请用户重新预选。这不是业务确认，而是缺少执行坐标的技术阻塞。

## 3. 如何正确识别图纸范围和图框

### 3.1 图框不是普通矩形，而是带属性的块参照

本图中的正式图框是 `BlockReference`，其属性中包含：

- `图名`
- `图号`
- `第页`
- `共页`
- `设计`
- `校对`
- `审核`
- `日期`

识别图框时，不依赖块名，也不依赖图层，而是查找属性标签 `图名`。示例：

```csharp
var br = entity as BlockReference;
if (br != null)
{
    string title = "";
    foreach (ObjectId aid in br.AttributeCollection)
    {
        var ar = tr.GetObject(aid, OpenMode.ForRead, false)
                 as AttributeReference;
        if (ar != null && ar.Tag == "图名")
            title = ar.TextString;
    }

    if (!string.IsNullOrEmpty(title))
    {
        // 这是正式图框
    }
}
```

这种方法能区分普通设备块、符号块和正式图框。

### 3.2 图框归属必须使用插入点，不能使用几何中心

本项目图框块的插入点位于图纸右下角。图框内部几何向左上方展开，属性文字还可能改变 `GeometricExtents`。因此：

- 普通图元可以使用包围盒中心判断属于哪张图；
- 正式图框必须使用 `BlockReference.Position` 判断位置；
- 不能用图框包围盒中心判断所属列。

如果用图框几何中心归类，长图名或块缓存范围可能导致图框被统计到左侧相邻图纸，出现“内容数量正确，但标题向左错一列”的假象。

正确做法：

```csharp
bool isTargetFrame =
    Math.Abs(br.Position.X - expectedFrameX) < 1.0 &&
    Math.Abs(br.Position.Y - expectedFrameY) < 1.0;
```

### 3.3 普通图元使用包围盒中心归属

对 `Line`、`DBText`、`Circle`、`Polyline`、普通块等顶层实体，可以使用几何包围盒中心判断是否在图纸单元内：

```csharp
var ex = entity.GeometricExtents;
double cx = (ex.MinPoint.X + ex.MaxPoint.X) / 2.0;
double cy = (ex.MinPoint.Y + ex.MaxPoint.Y) / 2.0;

bool inside =
    cx > left + tolerance &&
    cx <= right + tolerance &&
    cy >= bottom - tolerance &&
    cy < top - tolerance;
```

边界采用左开右闭，是为了避免处于相邻图纸边界上的图元被重复计入。

### 3.4 识别一张图的完整顶层实体集合

推荐算法如下：

1. 找到母版图框的句柄和插入点；
2. 将图框句柄本身强制加入源集合；
3. 其他带 `图名` 属性的正式图框全部排除；
4. 其余顶层实体按包围盒中心判断是否位于该图纸单元；
5. 检查实体总数是否和母版统计值一致。

本次任务的已验证实体数：

| 图纸 | 顶层实体数 | Line 数 |
|---|---:|---:|
| 1#供油泵控制原理图 | 502 | 213 |
| 1#卸油泵控制原理图 | 470 | 202 |
| AP2供油泵外部接线/端子母版 | 1005 | 621 |
| AP1卸油泵外部接线/端子母版 | 757 | 465 |
| AC柜参考图（二） | 252 | 131 |
| AC柜参考图（三） | 229 | 118 |

实体数是重要的保护条件。源集合数量异常时应抛出异常并停止事务，避免复制半张图。

### 3.5 从图框插入点推导网格布局

本次图纸的横向步距约为：

```text
sheetStepX = 72028.3418435604
```

图框有效高度约为：

```text
sheetHeight = 50081.67565047
```

当前两排图框插入点的 Y 差值约为：

```text
rowGap = 51571.6452116484
```

行距应通过两排图框插入点计算，而不是直接等同于图框高度。这样可以保留原图中的行间空隙。

布局规则：

```text
第一排：供油泵1# → 供油泵2# → 供油泵3# → 供油泵外接/端子图
第二排：卸油泵1# → 卸油泵2# → 卸油泵3# → 卸油泵外接/端子图
第三排：PLC图（二） → PLC图（三），与上方最左侧图框对齐
```

目标位置生成前必须扫描对应单元，确认实体数为 0。

## 4. 如何组织 `send_code_to_cad` 代码

### 4.1 一张图一次调用

每次 `send_code_to_cad` 只生成一张图，典型顺序是：

1. 供油泵2#控制图；
2. 供油泵3#控制图；
3. 供油泵外部接线/端子排图；
4. 卸油泵2#控制图；
5. 卸油泵3#控制图；
6. 卸油泵外部接线/端子排图；
7. PLC接线图（二）；
8. PLC接线图（三）；
9. 统一只读校核。

这样做便于定位单张图的错误，也能避免一段代码过长导致整批失败。

### 4.2 使用显式文档锁和事务

动态代码使用 `transactionMode: "none"`，由 C# 显式管理事务：

```csharp
var doc = Application.DocumentManager.MdiActiveDocument;
var db = doc.Database;

using (doc.LockDocument())
using (var tr = db.TransactionManager.StartTransaction())
{
    // 读取、克隆、变换、修改

    tr.Commit();
    return new { sheet = "2#供油泵控制原理图", created = count };
}
```

在 `Commit` 之前检查所有前置条件。任何异常都会阻止提交。

### 4.3 只克隆并变换顶层实体

使用 `Database.DeepCloneObjects` 克隆母版：

```csharp
var sourceIds = new ObjectIdCollection();
var sourceSet = new HashSet<ObjectId>();

// 将母版顶层实体同时加入 sourceIds 和 sourceSet

var map = new IdMapping();
db.DeepCloneObjects(sourceIds, modelSpace.ObjectId, map, false);
```

`IdMapping` 中除了顶层实体，还可能包含属性、嵌套对象或其他依赖项。变换时必须限制为原始顶层实体对应的克隆：

```csharp
foreach (IdPair pair in map)
{
    if (!pair.IsCloned || !sourceSet.Contains(pair.Key))
        continue;

    var entity = tr.GetObject(pair.Value, OpenMode.ForWrite, false)
                 as Entity;
    if (entity == null)
        continue;

    entity.TransformBy(matrix);
}
```

如果对 `IdMapping` 中所有克隆对象都执行 `TransformBy`，嵌套对象可能触发 `eNotApplicable`，甚至发生重复变换。

### 4.4 位移矩阵

控制图通常只做水平平移：

```csharp
var matrix = Matrix3d.Displacement(
    new Vector3d(sheetStepX * copyIndex, 0, 0));
```

外部接线图和 PLC 图使用目标图框插入点与参考图框插入点的差值：

```csharp
var matrix = Matrix3d.Displacement(
    new Vector3d(targetFrameX - sourceFrameX,
                 targetFrameY - sourceFrameY,
                 0));
```

### 4.5 修改顶层文字和图框属性

需要处理：

- `DBText.TextString`
- `MText.Contents`
- 图框块中的 `AttributeReference`

图框属性应按标签明确修改：

```csharp
if (attribute.Tag == "图名")
    attribute.TextString = "AP2柜控制原理图（2#供油泵）";
else if (attribute.Tag == "图号")
    attribute.TextString = "21906-630-091-08-2";
else if (attribute.Tag == "第页")
    attribute.TextString = "1";
else if (attribute.Tag == "共页")
    attribute.TextString = "2";
```

## 5. 如何判断哪些编号要改、哪些不能改

### 5.1 线号只替换完整的三位原理号

线号规则：

```text
1xx → 2xx 或 3xx
```

只替换整段文本完全匹配的三位数：

```csharp
if (Regex.IsMatch(text, @"^1\d{2}$"))
    text = targetDigit + text.Substring(1);
```

这样不会误改图号、日期、电压、设备参数或长编号中的数字。

本次校核结果：

- 每台供油泵包含 40 类有效线号；
- 每台卸油泵包含 37 类有效线号；
- 1#、2#、3#的线号后两位集合完全一致；
- 不同泵之间首位不同，因此不会产生跨回路线号冲突。

### 5.2 卸油泵编号规则

卸油泵母版使用：

- 电机：`M1`、`M1f`
- 按钮盒：`BX1`
- 控制元件：`KA1.x`、`KM1f`、`KH1f`、`QL1`、`UF1`、`FU1`、`SA1`、`SE1`、`SF1`、`SS1`、`PA1`、`TA1` 等

生成规则：

| 母版 | 2#卸油泵 | 3#卸油泵 |
|---|---|---|
| M1 / M1f | M2 / M2f | M3 / M3f |
| BX1 | BX2 | BX3 |
| KA1.0 | KA2.0 | KA3.0 |
| 101 | 201 | 301 |
| 1#卸油泵 | 2#卸油泵 | 3#卸油泵 |

`AP1` 是柜号，不能因为包含数字1而改为 AP2 或 AP3。

### 5.3 供油泵编号规则

供油泵采用两套编号体系：

1. 控制元件和原理线号仍按首位 1、2、3 变化；
2. 实际电机和就地按钮盒从 4 开始编号。

| 母版 | 2#供油泵 | 3#供油泵 |
|---|---|---|
| M4 / M4f | M5 / M5f | M6 / M6f |
| BX4 | BX5 | BX6 |
| KA1.0 | KA2.0 | KA3.0 |
| 101 | 201 | 301 |
| 1#供油泵 | 2#供油泵 | 3#供油泵 |

`AP2` 是供油泵所在柜号，必须保持不变。

因此供油泵不能简单地把所有编号首位 1 改为 2 或 3；`M4/BX4` 必须单独映射为 `M5/BX5` 和 `M6/BX6`。

### 5.4 元件前缀采用白名单

对元件编号使用前缀白名单，而不是匹配所有字母数字组合：

```regex
\b(KA|KM|KH|QL|UF|FU|BX|SA|SE|SF|SS|M|PA|TA)1(?=([A-Za-z.]|\b))
```

供油泵中的 `M4`、`BX4` 先单独替换；其他元件再使用白名单规则。

### 5.5 正则替换必须使用 `MatchEvaluator`

下面的写法是错误的：

```csharp
Regex.Replace(text, pattern, "$1" + "2");
```

拼接后实际替换字符串是 `$12`。正则引擎可能将它解释为第12捕获组，或直接留下字面量 `$12`，导致 `KA1.1`、`KM1f` 等元件号损坏。

正确写法：

```csharp
text = Regex.Replace(
    text,
    pattern,
    match => match.Groups[1].Value + "2");
```

生成后还应主动扫描 `$12`、`$13` 等字面量泄漏。

### 5.6 说明文字也要更新

母版说明通常描述“2#、3#与1#相同，仅改编号”。复制后如果原文不更新，单张图的说明会产生歧义。因此应将说明改成当前图纸的确定性描述，例如：

```text
本图为2#供油泵（M5）的控制原理图，元件号和原理号第一位均为“2”。
控制方式、联锁关系和PLC I/O功能与1#供油泵相同。
就地按钮盒编号与对应电机编号保持一致。
```

## 6. 如何生成外部接线图和端子排图

### 6.1 优先复用项目内的完整参考图

外部接线与端子排包含大量跨设备关系：

- 电机和按钮盒编号；
- 电缆号；
- 柜内端子号；
- PLC 通道；
- 变频器运行、启停及模拟量信号；
- 现场设备与柜内设备的对应关系。

如果完全从控制原理图重新推导并逐根画线，错误风险很高。本任务在原 DWG 中找到了已经完整表达三台泵关系的参考图，因此采用“整张深克隆 + 定位 + 改图签”的方式。

参考母版：

- AP2柜供油泵外部接线图：包含 `BX4/BX5/BX6`、AP2端子及三台供油泵的 PLC 信号；
- AP1柜卸油泵外部接线图：包含 `BX1/BX2/BX3`、AP1端子及三台卸油泵的 PLC 信号。

### 6.2 为什么整张克隆比局部拼接可靠

整张克隆能同时保留：

- 原图层；
- 线型和颜色；
- 端子符号；
- 电缆标注；
- 线号位置；
- 文字样式；
- 图框和图签；
- 已经验证过的连接拓扑。

生成后只修改图名、图号和摆放位置，不改动内部已正确的三台泵接线关系。

### 6.3 外部接线图的跨图检查

供油泵图至少检查：

```text
BX4, BX5, BX6
AP2-24 ... AP2-35
AP2-38, AP2-39
```

卸油泵图至少检查：

```text
BX1, BX2, BX3
AP1-24 ... AP1-35
```

校核时把图纸中的所有文本放入 `HashSet<string>`，使用必需编号清单计算缺失项。结果应为：

```json
{
  "supplyExternalMissing": [],
  "unloadExternalMissing": []
}
```

## 7. 如何生成 PLC 接线图

### 7.1 参考来源

PLC接线图参考项目中的：

- `AC柜外部接线图（二）`
- `AC柜外部接线图（三）`

两张参考图分别覆盖模拟量、状态反馈以及启停输出等内容。生成时整张克隆到第三排，并改名为：

- `AC柜PLC接线图（二）`
- `AC柜PLC接线图（三）`

同时设置新图号和页码：

```text
图（二）：第1页，共2页
图（三）：第2页，共2页
```

### 7.2 第三排左对齐

第三排第一张 PLC 图的图框插入点 X，取上方选中图纸最左侧图框的插入点 X；第二张图再向右移动一个 `sheetStepX`。

第三排 Y：

```text
thirdRowY = secondRowY - rowGap
```

不能把图框高度直接当行距，否则会丢失原有行间空白。

### 7.3 PLC 信号覆盖检查

两张 PLC 图合并检查以下关键通道：

```text
AI04
AO01
DI01
DI02
DI03
DO01
```

同时检查 AP1、AP2 外部接线图使用的端子/电缆引用是否在 PLC 图中出现。例如：

```text
AP1-24 ... AP1-35
AP2-24 ... AP2-35
AP2-38, AP2-39
```

最终结果应为：

```json
{
  "plcMissing": []
}
```

## 8. 如何进行最终检查

检查不能只看“代码执行成功”，需要从结构、编号、拓扑和跨图关系四层进行。

### 8.1 图纸结构检查

每张生成图检查：

- 顶层实体总数；
- `Line` 数量；
- 图框插入点；
- 图名、图号、页码；
- 目标单元是否只包含一张图。

控制图的生成结果必须与母版一致：

| 回路 | 母版实体数 | 2#实体数 | 3#实体数 | 母版Line数 | 2#/3# Line数 |
|---|---:|---:|---:|---:|---:|
| 供油泵 | 502 | 502 | 502 | 213 | 213 |
| 卸油泵 | 470 | 470 | 470 | 202 | 202 |

### 8.2 线号检查

对每张控制图收集完整三位线号，并去掉首位后比较后两位集合：

```text
供油泵：1#、2#、3#均为40类
卸油泵：1#、2#、3#均为37类
```

校核条件：

```csharp
sourceSuffixes.SetEquals(copy2Suffixes) &&
sourceSuffixes.SetEquals(copy3Suffixes)
```

这能发现漏改、错改或缺失线号。不同泵使用不同百位，避免跨泵重复。

### 8.3 元件和触点检查

提取完整匹配的元件标签，将泵序号归一化为 `#`，再比较每个标签的出现次数：

```text
KA1.1 / KA2.1 / KA3.1 → KA#.1
KM1f / KM2f / KM3f   → KM#f
M4 / M5 / M6         → M#
BX4 / BX5 / BX6      → BX#
```

不仅比较“是否出现”，还比较出现次数。触点标签签名完全一致，才认为没有缺失触点。

同时扫描：

- 2#、3#图中是否残留不应出现的 1#元件号；
- 供油泵图中是否残留 `M4`、`BX4`；
- 卸油泵图中是否残留 `M1`、`BX1`；
- 是否出现 `$12`、`$13` 等错误文本。

### 8.4 悬空导线检查

不能简单要求“度数为1的端点数量等于0”，因为端子、箭头、跨页连接等本来就会形成合法单端点。

更可靠的办法是建立导线拓扑签名：

1. 收集每条 `Line` 的起点和终点；
2. 将坐标相对图纸左下角归一化；
3. 按容差量化坐标；
4. 统计每个节点的连接度；
5. 比较母版、2#、3#的节点度分布和度数为1的端点数量。

本次结果：

```text
供油泵：三张图 degree-1 端点均为273
卸油泵：三张图 degree-1 端点均为255
```

因为生成图是母版的完整平移克隆，Line数和端点拓扑签名完全一致，可以判定没有新增悬空导线。若需判断母版本身是否存在设计错误，还应进一步结合端子、圆点、箭头和多段线建立更完整的网络模型。

### 8.5 外接、端子和 PLC 跨图检查

将外部接线图、端子排图和两张 PLC 图的文字分别收集成集合，再对必需信号做差集：

```csharp
var missing = required.Where(x => !actualTexts.Contains(x)).ToArray();
```

三类结果都应为空数组：

```json
{
  "supplyExternalMissing": [],
  "unloadExternalMissing": [],
  "plcMissing": []
}
```

## 9. 关键经验和常见陷阱

### 9.1 不要使用图框几何中心确定图纸列

正式图框必须用插入点。几何中心可能受属性文字、块缓存和长图名影响。

### 9.2 不要对 `IdMapping` 中所有对象执行变换

只变换源顶层实体对应的克隆对象。嵌套对象可能不支持独立变换。

### 9.3 不要使用 `$1` 与数字直接拼接的替换字符串

`"$1" + "2"` 会形成 `$12`。必须使用 `MatchEvaluator`。

### 9.4 不要把所有数字1都替换

AP1、AP2、图号、日期、页码、通道号等都有独立含义。使用完整格式、前缀白名单和特殊映射表。

### 9.5 不要从零重画已经存在的完整参考图

外部接线、端子排和 PLC 图包含大量已验证关系。优先整张克隆项目内参考图，再改图签和位置。

### 9.6 目标区域必须先确认为空

复制前统计目标图纸单元。如果非空，应判断是用户原图、上次生成结果还是其他对象，不能盲目叠加。

### 9.7 超时不等于执行失败

如果 `send_code_to_cad` 返回超时和 `callId`，应使用 `get_execution_status` 查询最终状态，不能立即重发相同写操作，否则可能重复生成。

### 9.8 校核要比较“与母版一致”，而不是只检查绝对值

合法端点、重复出现的线号标注、多个同名辅助触点都可能是设计需要。检查重点是：

- 复制前后数量是否一致；
- 编号映射是否一致；
- 拓扑签名是否一致；
- 跨图必需引用是否齐全。

## 10. 推荐的通用执行流程

```text
读取当前文档和预选集
  ↓
识别带“图名”属性的图框
  ↓
按图框插入点排序，确定行、列、步距和行距
  ↓
按图框句柄 + 普通实体包围盒中心提取母版
  ↓
统计母版实体类型、文字、线号、元件标签和拓扑签名
  ↓
扫描所有目标单元，确认为空
  ↓
逐张 DeepClone 控制图并执行语义化编号替换
  ↓
整张克隆外部接线/端子排参考图
  ↓
整张克隆 PLC 参考图并左对齐放置
  ↓
统一校核实体数、Line数、线号集合、元件签名、端点拓扑和跨图信号
  ↓
仅在所有检查通过后报告完成
```

## 12. 总结

这类任务的关键不是“复制并改数字”，而是建立稳定的图纸语义模型：

1. 用图框属性识别图纸；
2. 用图框插入点建立二维布局；
3. 用句柄和空间归属提取完整母版；
4. 用编号分类和白名单执行语义替换；
5. 用已有项目图纸复用复杂跨图关系；
6. 用结构、编号、拓扑和跨图引用完成闭环校核。

只有同时满足“图形一致、编号正确、连接完整、跨图对应齐全”，才算真正完成电气 CAD 图纸的自动生成。
