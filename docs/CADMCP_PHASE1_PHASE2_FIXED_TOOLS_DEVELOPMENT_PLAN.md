# CADMCP 固定工具第一、第二阶段开发计划

## 1. 文档目的

本文档用于规划 CADMCP 在现有 **9 个固定功能 + 1 个 `send_code_to_cad` 动态功能**基础上的第一、第二阶段扩展。

本文档只定义产品需求、工具接口、开发顺序、技术约束和验收方法，不包含本轮代码实现，也不调整任何产品版本、TCP 协议版本或设置架构版本。

计划主要来自以下已反复出现的实际使用场景：

- 读取当前选中图纸，识别多张图的范围和排列关系。
- 将已有控制原理图复制成 2#、3# 回路，并批量修改元件编号、线号和 PLC 信号。
- 根据控制原理图生成外部接线图、端子排图和 PLC 接线图。
- 重排板卡阵列、复制整张子图并保持图层、文字、线型和间距一致。
- 根据 `R4`、引线和几何位置判断标注指向的具体圆弧，并在 CAD 中精确选中目标实体。
- 发现生成结果不正确时，准确定位并删除本次生成的实体。

## 2. 当前能力与主要缺口

当前固定工具擅长连接测试、读取文档、读取选择集、按条件查询以及创建直线、多段线、圆和文字。`send_code_to_cad` 可以在 AutoCAD 进程内执行复杂 C#，能力完整，但每次都需要临时编写实体遍历、事务、句柄解析、几何判断和异常处理代码。

现阶段的主要缺口不是“不能完成任务”，而是常见操作尚未形成稳定、可复用、参数可校验的固定工具：

1. 能读到实体摘要，但不能稳定获得圆弧、引线、属性块、尺寸等实体的完整信息。
2. 能读取选择集，但不能通过句柄精确改写 CAD 当前选择集。
3. 能创建基础实体，但缺少对已有实体的复制、移动、旋转、批量改字和安全删除。
4. 能按包围盒查询实体，但不能直接识别多张图的图框、行列和图内实体归属。
5. 能获得邻近实体，但缺少“标注到底指向哪个几何对象”的结构化判断。

因此，固定工具的定位应是：把高频、通用、边界清楚的 CAD 操作固化；复杂的整图推理和一次性绘图逻辑继续由 AI 通过多个固定工具编排，必要时再使用 `send_code_to_cad`。

## 3. 阶段目标

### 第一阶段：建立已有图形的安全编辑闭环

第一阶段完成后，AI 应能在不临时编写 C# 的情况下：

1. 按句柄读取实体完整信息。
2. 精确设置当前选择集。
3. 复制整张子图并保持原属性。
4. 对实体进行移动、旋转、缩放和镜像。
5. 批量替换普通文字、多行文字和块属性中的编号。
6. 单独修改块属性。
7. 预览并安全删除指定实体。

这阶段解决的是“已经理解了图纸以后，怎样稳定地修改图纸”。

### 第二阶段：建立图纸范围和几何语义理解能力

第二阶段完成后，AI 应能：

1. 查询某一点或实体附近的候选对象，并取得精确距离。
2. 识别当前图中的图框、图名、行列、相邻关系和间距。
3. 可靠取得某一个图框内的实体集合。
4. 判断文字、引线、箭头或半径标注具体指向哪个几何对象。

这阶段解决的是“面对多张并排或上下排列的图，怎样正确理解每张图的边界，以及标注与实体之间的关系”。

## 4. 总体设计原则

### 4.1 固定工具与动态代码的边界

- 固定工具承担可复用的原子能力，例如复制、移动、替换文字、识别图框和解析标注目标。
- `send_code_to_cad` 保留为核心兜底能力，处理尚未固化的实体类型、特殊行业规则和复杂整图生成。
- 不建议第一、第二阶段直接开发“生成卸油泵控制图”或“生成 PLC 接线图”这类行业专用单体命令。它们应由图框识别、整图复制、编号替换、块属性修改等通用工具编排完成。
- 当固定工具无法覆盖某种特殊实体时，应明确返回 `unsupported_entity_type`，允许 AI 决定是否切换到 `send_code_to_cad`，不能静默忽略。

### 4.2 实体身份

- 对外稳定标识统一使用 AutoCAD `Handle`。
- `ObjectId` 只用于一次 CAD 调用内部，不应被 MCP 客户端长期保存或作为后续调用的主键。
- 所有以句柄为输入的工具必须一次性解析并验证全部句柄；写操作只有在全部目标验证成功后才能开始修改。
- 返回结果需同时包含成功处理的句柄、跳过项、警告和失败原因。

### 4.3 单位与坐标系

- MCP 对外长度单位继续统一为毫米。
- 几何输入必须显式支持 `ucs`、`wcs`，默认值应与现有工具一致。
- 几何查询结果应统一返回 WCS 坐标，并写明 `coordinateSystem: "wcs"` 与 `unit: "Millimeters"`。
- 角度单位统一为弧度；若未来支持角度制，应使用独立字段，不能根据数值自动猜测。

### 4.4 原子性、撤销与可预览

- 所有写工具沿用现有 `AtomicCreateCommand` 的模式：文档锁、单事务、显式撤销边界、全部成功后提交。
- 批量修改或删除中任意一项失败时，整个调用回滚，不能只完成一部分。
- 高风险工具提供 `dryRun`，其中删除工具默认 `dryRun: true`。
- 批量写操作支持 `expectedCount`。实际目标数量不一致时返回 `count_mismatch`，不得修改图纸。
- 成功结果继续返回 `committed`、`rolledBack`、`undoGuaranteed` 和警告信息。

### 4.5 活动文档和活动空间

- 第一、第二阶段默认只处理当前活动 DWG 的当前空间。
- 句柄属于其他空间时应返回明确错误，不能把实体误写到模型空间或其他布局。
- 第一版不处理跨文档复制、外部参照内部实体和块定义内部实体的直接编辑。
- 所有工具必须在 CAD 空闲状态下执行，并继续受当前单调用槽控制。

### 4.6 结果可解释性

几何推理类工具不仅返回“结论”，还要返回判断依据。例如标注目标解析应返回箭头端点、最近点、距离、候选排序和置信度。这样 AI 可以复核结论，也方便定位算法错误。

## 5. 建议的公共数据结构

为了避免 11 个工具各自定义一套目标选择方式，建议先建立公共输入模型。

### 5.1 `EntitySource`

```json
{
  "source": {
    "kind": "handles",
    "handles": ["1A2", "1A3"]
  }
}
```

`kind` 第一阶段支持：

- `handles`：显式句柄，最安全，适合后续修改。
- `selection`：使用调用开始时捕获的预选集。
- `query`：复用 `query_entities` 的类型、图层、线型、颜色和包围盒条件。

写操作中如使用 `selection` 或 `query`，应强烈建议同时传入 `expectedCount`。

### 5.2 通用实体摘要

所有返回实体的工具应复用同一份摘要：

```json
{
  "handle": "1A2",
  "type": "ARC",
  "layer": "E-CONTROL",
  "linetype": "ByLayer",
  "color": { "mode": "byLayer" },
  "visible": true,
  "boundingBoxWcs": {},
  "geometry": {}
}
```

不建议继续把运行期 `OldIdPtr` 暴露为可复用的 `objectId`；如果保留，应注明它只对当前会话具有诊断意义。

### 5.3 建议错误码

| 错误码 | 含义 |
| --- | --- |
| `invalid_parameters` | 参数结构、单位或数值无效 |
| `entity_not_found` | 句柄不存在、已删除或无效 |
| `wrong_entity_type` | 实体类型不满足本工具要求 |
| `unsupported_entity_type` | 当前版本尚不支持该实体类型 |
| `entity_outside_active_space` | 实体不在当前活动空间 |
| `count_mismatch` | 实际目标数与 `expectedCount` 不一致 |
| `missing_resource` | 图层、线型、文字样式等资源缺失 |
| `ambiguous_target` | 有多个接近的候选目标，无法可靠唯一判断 |
| `dependent_entity` | 外部参照或其他依赖实体禁止直接修改 |
| `geometry_unavailable` | 实体没有可用几何范围或几何信息 |

## 6. 第一阶段功能计划

### 6.1 `get_entity_details` — 按句柄读取实体详情

#### 如何使用

```json
{
  "handles": ["1A2", "1A3"],
  "includeGeometry": true,
  "includeAttributes": true,
  "includeStyle": true
}
```

#### 解决的问题

`get_selected_entities` 和 `query_entities` 目前只能为少数实体提供完整几何信息。处理圆弧、引线、尺寸、块属性和普通单行文字时，经常仍需用 `send_code_to_cad` 逐类读取属性。

本工具应成为“已知句柄后获取事实”的稳定入口。

#### 对应的常见画图操作

- 读取 `R4` 文字、两条引线和附近圆弧的端点、圆心、半径及角度范围。
- 读取控制原理图里的元件编号、线号、PLC 信号和块属性。
- 读取图框块的插入点、有效块名和“图名”等属性。
- 复制或改号前，确认文字是 `TEXT`、`MTEXT` 还是属性块。

#### 第一版支持范围

- 基础图元：`LINE`、`ARC`、`CIRCLE`、`LWPOLYLINE`、`POLYLINE`、`SOLID`。
- 文字：`TEXT`、`MTEXT`。
- 标注：`LEADER`、`MLEADER`、常见 `DIMENSION`。
- 块：`INSERT`，包括有效块名、动态块名、变换矩阵和可见属性引用。
- 其他类型至少返回公共摘要；几何不支持时返回 `geometry: null` 和警告。

#### 开发注意事项

- 扩展 `commandset/EntitySerialization.cs`，不要在新命令中复制序列化逻辑。
- 圆弧必须返回圆心、半径、起止角、起止点和法向量；仅有包围盒不足以判断标注指向。
- `TEXT` 应分别返回原始文本、位置、对齐点、旋转、文字高度和文字样式。
- `MTEXT` 同时返回原始 `Contents` 和便于搜索的纯文本，防止格式控制码影响编号匹配。
- 块属性应返回 `tag`、`text`、位置、是否常量和属性引用句柄。
- 动态块优先返回 `DynamicBlockTableRecord` 对应的有效名称，不能只返回匿名块名。
- 引线应按顺序返回全部顶点；多重引线应保留 leader line 与 content 的层级关系。

#### 验收标准

- 对同一实体连续读取结果稳定。
- 输出坐标均为 WCS、长度均为毫米。
- 能完整支持 R4 场景和常用电气图实体。
- 输入中存在任意无效句柄时，不返回一半成功、一半失败的模糊结果。

### 6.2 `set_selection` — 精确设置 CAD 当前选择集

#### 如何使用

```json
{
  "mode": "replace",
  "handles": ["2B1", "2B2"],
  "expectedCount": 2
}
```

`mode` 支持 `replace`、`add`、`remove`、`clear`。

#### 解决的问题

当前工具可以读取预选集，却不能把分析出的目标实体反馈到 CAD 界面。精确选中对象目前需要动态代码调用 `Editor.SetImpliedSelection`。

#### 对应的常见画图操作

- 判断两个 `R4` 分别指向哪段圆弧后，直接选中这两个圆弧供用户查看。
- 生成图纸后，选中新创建的一张子图或本次创建的全部实体。
- 校核发现悬空导线、重复线号或缺失触点后，选中问题对象。

#### 开发注意事项

- 解析和验证全部句柄后再调用 `SetImpliedSelection`。
- `replace` 失败时应保持原选择集不变。
- `add` 和 `remove` 应去重，并保持确定性的句柄顺序。
- 应拒绝选择不可用、已删除或不属于活动文档的对象。
- `CadDispatcher` 当前会在命令前后捕获并恢复选择集；实现时需明确允许 `set_selection` 的最终选择结果成为新的持久选择集，不能被调度器的通用恢复逻辑覆盖。
- 返回 `previousHandles`、`selectedHandles`、`count`。

#### 验收标准

- 调用结束后，AutoCAD 界面中的预选集与返回句柄一致。
- `clear` 可稳定清空选择集。
- 数量不符或有无效句柄时不改变原选择集。

### 6.3 `clone_entities` — 原样复制实体集合

#### 如何使用

```json
{
  "source": { "kind": "selection" },
  "displacement": { "x": 420, "y": 0, "z": 0 },
  "coordinateSystem": "wcs",
  "expectedCount": 186,
  "selectCreated": false
}
```

#### 解决的问题

现有创建工具适合从零画基础对象，但复制一张已有的电气图时，逐一重建实体容易丢失图层、线型、颜色、文字样式、块属性、尺寸样式和对象间距。

#### 对应的常见画图操作

- 将 1# 供油泵或卸油泵控制原理图复制到右侧作为 2#、3# 的基础。
- 复制外部接线图和端子排图后再改编号。
- 复制板卡阵列并改变排列。
- 把一张完整子图复制到下方或右侧空白区域。

#### 开发注意事项

- 第一版只允许复制当前空间中的顶层实体。
- 使用数据库克隆机制保留实体的完整数据库属性，避免通过序列化再创建造成样式损失。
- 复制完成后统一施加位移矩阵。
- 需要明确属性块复制后的属性引用、动态块状态和可见性参数保持不变。
- 禁止直接复制外部参照内部对象；遇到依赖对象返回 `dependent_entity`。
- 必须返回稳定的 `sourceHandle -> createdHandle` 映射，供后续 `replace_text`、`set_block_attributes` 和删除操作使用。
- 不自动复制图层、线型等符号表资源；同一 DWG 当前空间复制应直接复用已有资源。
- `selectCreated` 可选，默认关闭，避免批量生成中频繁改变用户选择集。

#### 验收标准

- 复制结果与源图在图层、线型、颜色、文字样式、块属性和几何间距方面一致。
- 位移误差在 CAD 数据精度范围内。
- 任一对象不能复制时整体回滚。
- 复制 1000 个常见二维实体时不得触发明显的逐实体界面刷新。

### 6.4 `transform_entities` — 批量几何变换

#### 如何使用

移动：

```json
{
  "source": { "kind": "handles", "handles": ["31A", "31B"] },
  "operation": {
    "type": "move",
    "displacement": { "x": 0, "y": -300, "z": 0 }
  },
  "coordinateSystem": "wcs",
  "expectedCount": 2
}
```

镜像：

```json
{
  "source": { "kind": "selection" },
  "operation": {
    "type": "mirror",
    "axisStart": { "x": 0, "y": 0, "z": 0 },
    "axisEnd": { "x": 0, "y": 100, "z": 0 }
  },
  "expectedCount": 48
}
```

#### 解决的问题

复制完成后经常需要将整张图平移到右侧、下方，或对阵列进行镜像和重新排列。若每次动态生成矩阵代码，参数错误会直接影响大量实体。

#### 对应的常见画图操作

- 将 2#、3# 泵图按既有图宽和间距排列到右侧。
- 把外部接线图、端子排图或 PLC 图移到指定行并左对齐。
- 将 3 行 6 列板卡从“右到左、上到下”重排为“左到右、下到上”。
- 纠正生成图与参考图之间的整体偏移。

#### 开发注意事项

- 第一版支持 `move`、`rotate`、`scale`、`mirror`，每次调用只执行一种变换。
- 旋转必须要求基点；缩放必须要求基点和正数比例；镜像必须要求不重合的轴线两点。
- `mirror` 默认修改原实体的位置，不创建副本；复制加镜像应先调用 `clone_entities`，避免一个工具同时包含两种语义。
- 对二维图，默认围绕 WCS Z 轴旋转。
- 对非均匀缩放、带约束对象和注释性对象，第一版可明确不支持。
- 返回每个句柄变换前后的包围盒，方便调用方检查整体位置。

#### 验收标准

- 批量变换保持实体属性不变。
- 任一变换参数无效时整体不修改。
- UCS 非世界坐标状态下，`ucs` 和 `wcs` 的结果可区分且正确。

### 6.5 `replace_text` — 受控批量改号

#### 如何使用

```json
{
  "source": { "kind": "handles", "handles": ["401", "402", "403"] },
  "rules": [
    { "mode": "exact", "from": "1KM1", "to": "2KM1" },
    { "mode": "regex", "pattern": "^1(\\d{2})$", "replacement": "2$1" }
  ],
  "entityKinds": ["TEXT", "MTEXT", "ATTRIBUTE"],
  "dryRun": true,
  "expectedCount": 3
}
```

#### 解决的问题

泵回路复制后，元件编号、线号和 PLC 地址不是简单地把所有数字 `1` 替换成 `2`。需要只改符合规则的字段，同时保留电压、端子通用编号、图纸号、规格和固定公共信号。

#### 对应的常见画图操作

- 将 1# 泵回路复制为 2#、3# 后，替换元件编号首位。
- 根据既定编号规则修改线号和 PLC I/O 点位。
- 修改图名中的泵编号。
- 保留 `AC220V`、`24VDC`、端子位号、触点序号等不应改动的文字。

#### 功能要求

- 支持 `TEXT`、`MTEXT` 和块属性引用。
- 支持精确匹配、正则匹配和显式映射表。
- `dryRun` 返回每一项的句柄、实体类型、属性标签、原值、新值和命中规则，但不提交事务。
- 正式执行时允许传入 `expectedChanges`，预览数与实际修改数不一致则拒绝提交。
- 规则按数组顺序执行，并明确是“每个值只应用第一条命中规则”还是“连续应用全部规则”。建议第一版采用第一条命中即停止，减少二次替换。

#### 开发注意事项

- `MTEXT` 要尽量保留格式控制码，只替换文本内容段，不能因改号破坏换行、字体或堆叠格式。
- 块属性以属性引用文本为修改目标，不应修改块定义中的常量属性。
- 正则表达式需要设置合理的超时或限制，避免灾难性回溯阻塞 CAD 主线程。
- 默认大小写敏感；是否忽略大小写必须显式指定。
- 返回未命中规则的目标，便于发现漏改编号。
- 开发测试必须覆盖“编号中的 1 需要改”和“普通数字 1 不应改”的对照案例。

#### 验收标准

- `dryRun` 与正式执行的目标集合、命中规则和新值完全一致。
- 不改变文字位置、图层、样式、旋转和对齐方式。
- 正则或映射错误时整体不修改。
- 能用结构化规则完成 1# 泵到 2#、3# 泵的主要改号操作。

---

### 6.6 `set_block_attributes` — 精确修改块属性

#### 如何使用

```json
{
  "items": [
    {
      "blockHandle": "510",
      "attributes": {
        "图名": "2#供油泵控制原理图",
        "图号": "AC-02"
      }
    }
  ],
  "requireExistingTags": true,
  "dryRun": false
}
```

#### 解决的问题

图框标题、设备名称和图号常以块属性保存。把它们混在通用文字替换中会增加误改风险，也无法明确指定属性标签。

#### 对应的常见画图操作

- 复制整张图后修改图框中的“图名”“图号”“设备编号”。
- 更新端子排图或 PLC 接线图标题。
- 保持图框块本身的位置、比例和动态属性不变。

#### 开发注意事项

- 属性标签匹配建议默认不区分大小写，但返回实际标签拼写。
- `requireExistingTags: true` 时，任意标签不存在都应整体回滚。
- 第一版只修改现有 `AttributeReference.TextString`，不创建新的属性定义。
- 需要处理不可见属性，但结果中应返回 `invisible` 状态。
- `dryRun` 应返回原值和新值。

#### 验收标准

- 只修改指定块和指定标签。
- 不改变块插入点、比例、旋转和动态块参数。
- 标签缺失时错误信息能指出块句柄和缺失标签。

---

### 6.7 `erase_entities` — 可预览的安全删除

#### 如何使用

```json
{
  "source": { "kind": "handles", "handles": ["620", "621"] },
  "expectedCount": 2,
  "dryRun": true
}
```

#### 解决的问题

测试生成结果后，经常需要删除刚画出的整张图或少量错误实体。若动态代码中的选择范围判断错误，可能误删用户原图。

#### 对应的常见画图操作

- 删除本次生成的 2#、3# 控制原理图后重新测试。
- 删除错误生成的外部接线图、端子排图或 PLC 图。
- 清理重复线号文字、错误导线或多余触点。

#### 开发注意事项

- 默认 `dryRun: true`。
- 正式删除时要求显式传入 `dryRun: false` 和 `expectedCount`。
- 预览结果返回句柄、类型、图层和包围盒，方便 AI 再次确认范围。
- 仅删除当前空间中的顶层实体；块内实体、外部参照依赖对象和符号表记录不属于本工具范围。
- 所有句柄先验证后删除，任一失败则整体回滚。
- 返回已删除句柄，便于调用方清理缓存映射。

#### 验收标准

- 预览调用不改变 DWG 的 `DBMOD`。
- 正式调用可通过一次 AutoCAD 撤销恢复全部删除对象。
- `expectedCount` 不一致时不删除任何实体。

## 7. 第二阶段功能计划

### 7.1 `query_nearby_entities` — 邻近实体与精确距离查询

#### 如何使用

```json
{
  "reference": { "kind": "handle", "handle": "701" },
  "radius": 20,
  "entityTypes": ["ARC", "LINE", "LWPOLYLINE"],
  "distanceMode": "closestPoint",
  "sortBy": "distance",
  "limit": 20
}
```

也应支持以 WCS/UCS 点作为参考。

#### 解决的问题

包围盒重叠只能粗略筛选实体，不能回答“箭头尖端距离哪条弧最近”“文字附近有哪些候选线段”。此前需要动态代码先粗筛，再逐实体调用最近点算法。

#### 对应的常见画图操作

- 查找 `R4` 文字、引线端点附近的圆弧。
- 查找某个端子号附近的导线和端子块。
- 检查线号文字与实际导线是否邻近。
- 为外部接线图寻找对应建筑图中的控制点位。

#### 开发注意事项

- 先用扩大后的几何包围盒进行候选预筛，再计算精确距离，避免对全图做昂贵计算。
- `closestPoint` 应基于实体实际曲线，而不是包围盒中心。
- 返回参考点、目标最近点、距离、实体摘要和排序名次。
- 对不属于 `Curve` 的实体，应实现明确的距离策略或返回不支持警告。
- 对闭合多段线、圆和跨越 0 度的圆弧必须有边界测试。
- 限制最大半径、最大候选数和最大返回数，防止在大型建筑图中阻塞 CAD。

#### 验收标准

- 候选按实际几何距离稳定排序。
- 与人工测距结果在容差内一致。
- 大型图纸中先空间预筛，不因单次调用遍历并精算所有实体。

---

### 7.2 `detect_drawing_frames` — 识别图框、图名与阵列布局

#### 如何使用

```json
{
  "source": { "kind": "selection" },
  "titleAttributeTags": ["图名", "TITLE"],
  "rowTolerance": 20,
  "columnTolerance": 20,
  "includeUnresolved": true
}
```

#### 解决的问题

当选择集中有多张图时，最大矩形、块名或几何中心都可能误导范围判断。实际图框常是具有“图名”属性的块引用，块插入点可用于判断行列，但图框的实际覆盖范围还需要结合块变换、几何范围和相邻图间距。

#### 对应的常见画图操作

- 区分第一排 1# 供油泵图和第二排 1# 卸油泵图。
- 识别左上/右上的流程图与左下/右下的布线图。
- 确定 3 行 6 列板卡阵列的行列和递增方向。
- 取得每张图的宽度、高度、水平间距和垂直间距，为右侧或下方留出正确位置。

#### 建议输出

```json
{
  "frames": [
    {
      "handle": "801",
      "title": "1#供油泵控制原理图",
      "positionWcs": {},
      "boundsWcs": {},
      "row": 0,
      "column": 0,
      "confidence": 0.98,
      "evidence": ["attribute:图名", "blockReference", "rowCluster"]
    }
  ],
  "layout": {
    "rows": 2,
    "columns": 1,
    "horizontalPitch": null,
    "verticalPitch": 360
  }
}
```

#### 开发注意事项

- 核心识别依据应优先使用属性标签和值，不应依赖固定块名。
- 动态块和匿名块需要读取有效块名。
- 插入点适合行列聚类，但不能单独代表图框边界。
- 边界来源应在结果中标注，例如 `blockExtents`、`explicitPolyline`、`neighborInferred`。
- 行列聚类容差必须使用毫米输入，并考虑图纸轻微不对齐。
- 不确定的候选应返回 `confidence` 和 `warnings`，不能强行归类。
- 第一版只做识别，不移动任何实体。

#### 验收标准

- 能正确识别已选多张泵控制图的上下两排关系。
- 图框块名变化但“图名”属性存在时仍可识别。
- 选择集中混有普通矩形和设备块时，不把它们误认为图框。
- 返回的排序规则固定：先按行，再按列；行列方向写入结果说明。

---

### 7.3 `get_sheet_entities` — 获取指定图框内的实体

#### 如何使用

```json
{
  "frameHandle": "801",
  "membershipMode": "centerInside",
  "includeFrame": true,
  "excludeOtherFrames": true,
  "limit": 2000
}
```

#### 解决的问题

识别图框后，还必须准确知道哪些实体属于这张图。单纯按总选择集或包围盒相交查询，容易把相邻图、跨框线或其他图框一起包含进去。

#### 对应的常见画图操作

- 只复制第一排的 1# 供油泵图，不混入第二排卸油泵图。
- 分别取得控制原理图、外部接线图、端子排图和 PLC 图的实体范围。
- 在复制整张图后，仅对复制结果执行编号替换。
- 删除一张生成图时避免误删相邻原图。

#### 成员判定模式

- `centerInside`：实体包围盒中心在图框内，适合作为默认模式。
- `fullyInside`：实体包围盒完全位于图框内，最保守。
- `intersects`：实体包围盒与图框相交，适合查找跨边界对象，但误包含风险最高。

#### 开发注意事项

- 图框实体自身必须通过句柄显式加入，不能依赖其几何中心。
- 当多个图框重叠时，应根据最近图框中心、内部面积比例和相邻布局给出归属；无法唯一判断时返回 `ambiguous` 列表。
- 默认排除其他已识别图框及其属性引用。
- 返回 `handles`、`typeCounts`、`boundsWcs`、`ambiguousHandles` 和 `truncated`。
- 用于写操作前不得接受截断结果；若实体数超过限制，应返回错误或要求提高上限，不能让调用方误以为已取得整图。
- 可允许调用方传入 `expectedFrameBounds`，用于发现图框移动后缓存失效。

#### 验收标准

- 对上下相邻、左右相邻和轻微错位的图框均能正确分组。
- 图框属性文字归属于自己的图框。
- 相邻图中的实体不会因包围盒轻微相交而被默认模式包含。
- 结果可直接作为 `clone_entities` 或 `erase_entities` 的输入句柄集合。

---

### 7.4 `resolve_annotation_target` — 解析标注指向对象

#### 如何使用

```json
{
  "annotationHandles": ["901", "902"],
  "targetEntityTypes": ["ARC", "CIRCLE", "LINE", "LWPOLYLINE"],
  "searchRadius": 30,
  "maxCandidatesPerAnnotation": 5,
  "minimumConfidence": 0.75,
  "selectResolvedTargets": false
}
```

#### 解决的问题

文字内容本身无法说明它指向哪个实体。必须结合引线箭头端、标注定义点、文字位置、候选几何距离和标注语义共同判断。R4 场景正是这一能力的典型案例。

#### 对应的常见画图操作

- 判断两个 `R4` 分别对应哪部分圆弧。
- 根据引线确定元件编号或设备编号指向的图元。
- 根据尺寸标注确定被测线、圆或弧。
- 在流程图与布线图之间建立点位标注和实际位置的对应关系。

#### 判断逻辑建议

1. 识别标注实体类型及文字内容。
2. 提取引线箭头端、尺寸定义点或文字关联点。
3. 在搜索半径内调用邻近查询获得候选。
4. 计算箭头端到候选实际几何的最近距离。
5. 使用文字语义校验，例如 `R4` 优先匹配半径约为 4 mm 的圆弧或圆。
6. 综合距离、方向、是否位于实体有效参数范围和文字数值一致性打分。
7. 高于阈值且与次优候选差距足够时返回唯一目标；否则返回 `ambiguous_target` 和候选列表。

#### 建议输出

```json
{
  "items": [
    {
      "annotationHandle": "901",
      "text": "R4",
      "resolvedTargetHandle": "A01",
      "confidence": 0.96,
      "evidence": {
        "arrowTipWcs": {},
        "closestPointWcs": {},
        "distance": 0.08,
        "measuredRadius": 4.0,
        "textRadius": 4.0
      },
      "candidates": []
    }
  ]
}
```

#### 开发注意事项

- 工具必须区分 `LEADER`、`MLEADER`、半径尺寸和“文字 + 手动画线/实心箭头”的组合标注。
- 对组合标注，可允许输入多个注释句柄组成一组，或增加 `annotationGroups` 结构。
- 圆弧半径吻合只是证据之一，不能越过箭头端距离直接选择同半径的远处圆弧。
- 距离相近、半径相同的多个候选必须返回歧义，不能随机取第一个。
- 若 `selectResolvedTargets: true`，内部应复用 `set_selection` 服务，不要另写选择集逻辑。

#### 验收标准

- 可稳定解析此前两个 `R4` 标注对应的两段圆弧。
- 改变实体遍历顺序不影响最终结果。
- 歧义场景返回候选和证据，不产生虚假的高置信结论。
- 选择目标时，CAD 最终选择集与解析结果一致。

## 8. 典型组合流程

### 8.1 `R4` 圆弧判断与选中

```text
get_selected_entities
        ↓
get_entity_details（读取文字、引线和候选圆弧）
        ↓
query_nearby_entities（按箭头端粗筛和精确测距）
        ↓
resolve_annotation_target（结合 R4 数值与几何关系判断）
        ↓
set_selection（在 CAD 中选中两段圆弧）
```

该流程取代目前反复通过 `send_code_to_cad` 编写实体遍历、引线解析和选择集设置代码的做法。

### 8.2 从 1# 泵图扩展到 2#、3# 泵图

```text
detect_drawing_frames
        ↓
get_sheet_entities（取得 1# 图完整范围）
        ↓
clone_entities（复制到右侧）
        ↓
replace_text dryRun（预览元件号、线号、PLC 信号变化）
        ↓
replace_text 正式执行
        ↓
set_block_attributes（修改图名、图号）
        ↓
必要时使用 transform_entities 微调整体位置
```

卸油泵、供油泵、外部接线图和端子排图都可复用同一流程。编号规则仍由 AI 根据源图逻辑生成，固定工具只负责按结构化规则可靠执行。

### 8.3 生成结果清理

```text
clone_entities 返回 createdHandles
        ↓
后续创建工具继续累积本次 createdHandles
        ↓
erase_entities dryRun
        ↓
核对 expectedCount
        ↓
erase_entities 正式删除
```

不建议仅用大范围包围盒直接删除，因为图框附近可能有用户原有实体。

## 9. 代码结构建议

### 9.1 CommandSet 层

建议新增或抽取以下公共组件：

- `EntityTargetResolver`：统一解析句柄、初始选择集和查询条件。
- `EntitySerialization` 扩展：统一所有支持实体的详细序列化。
- `AtomicModifyCommand`：复用文档锁、撤销边界、事务、计数校验和统一响应。
- `GeometryRelationService`：最近点、几何距离、包围盒预筛和候选排序。
- `DrawingFrameService`：图框候选、属性读取、行列聚类和边界推断。
- `SheetMembershipService`：图框内部实体归属。
- `AnnotationResolutionService`：标注结构抽取、候选评分和歧义判断。

命令类保持薄层：负责参数解析、调用公共服务和封装响应，不应在每个命令中重复事务与句柄解析代码。

### 9.2 Plugin 层

需要关注：

- `plugin/CommandRegistry.cs` 会校验设置中声明的固定工具是否存在对应 `ICadCommand`。
- `plugin/CadDispatcher.cs` 当前统一捕获并恢复选择集；`set_selection` 需要定义特殊的选择持久化机制。
- `plugin/Settings.cs` 和 `plugin/SettingsWindow.cs` 需要加入新工具和中文说明。
- 写操作继续使用统一执行响应，避免为每个新工具发明不同的成功/失败格式。
- 建议把命令业务错误映射成稳定错误码，而不是全部在调度层变成 `execution_failed`。

### 9.3 Server 层

需要在 `server/src/tools/register.ts` 中：

- 为每个工具定义严格 Zod 模式。
- 使用判别联合表达 `EntitySource` 和变换操作，避免互斥参数同时出现。
- 设置数组数量、字符串长度、查询半径和返回数量上限。
- 在工具描述中明确毫米、坐标系、活动空间、原子性和 `dryRun` 默认值。
- 保持工具返回统一经过 `invokeCad` 和 `errorResult`。

建议将重复的 `point`、`color`、`EntitySource`、`expectedCount` 等模式拆到共享 schema 文件，避免 `register.ts` 继续膨胀。

## 10. 开发顺序与里程碑

### 里程碑 0：公共契约与基础设施

- 定义公共句柄解析、实体来源、计数校验、错误码和响应结构。
- 扩展实体序列化测试样例。
- 建立 `AtomicModifyCommand` 或等效公共执行框架。
- 明确选择集持久化与调度器恢复策略。

完成条件：后续命令无需各自重写事务、句柄解析和错误响应。

### 里程碑 1：读取与选择

- `get_entity_details`
- `set_selection`

完成条件：能不用动态代码完成 R4 相关实体的完整读取和句柄精确选择。

### 里程碑 2：复制与变换

- `clone_entities`
- `transform_entities`

完成条件：可把一张完整子图原样复制到指定位置，并保持属性和间距一致。

### 里程碑 3：文字、属性与删除

- `replace_text`
- `set_block_attributes`
- `erase_entities`

完成条件：可预览并完成泵编号替换、图框标题修改和生成结果整体清理。

### 里程碑 4：几何邻近能力

- `query_nearby_entities`

完成条件：能按真实几何距离返回候选，而不是只依赖包围盒。

### 里程碑 5：图框与子图范围

- `detect_drawing_frames`
- `get_sheet_entities`

完成条件：能正确拆分上下两排、左右多列的图纸，并把实体归入各自图框。

### 里程碑 6：标注解析与整体验收

- `resolve_annotation_target`
- 完成 R4、泵图复制改号和清理流程的端到端验证。

第二阶段依赖第一阶段的详细实体读取和选择工具，因此不建议跳过里程碑 1 直接实现标注解析。

## 11. 测试计划

### 11.1 Server 参数契约测试

现有 `server/tests` 已覆盖版本、会话、帧协议和 CAD 客户端。新工具至少补充以下测试：

- 合法参数可通过 Zod 校验并正确转发。
- 互斥字段不能同时出现。
- 空句柄、重复句柄、超长数组、负半径、无效坐标系被拒绝。

### 11.2 纯逻辑测试

建议将以下不依赖活动 AutoCAD 文档的算法抽成可测试代码：

- 图框成员归属。

- UCS/WCS 和毫米换算的边界案例。

- 成功执行。
- 输入无效时零修改。
- 中途失败时整批回滚。
- 一次 `UNDO` 恢复整次操作。
- 模型空间与布局空间不会串写。
- 非世界 UCS 下坐标处理正确。
- 当前选择集行为符合工具约定。
- 大批量实体不会逐项闪烁或导致长时间无响应。

重点业务样图：

1. 两个 `R4` 标注对应两段圆弧。
2. 第一排供油泵、第二排卸油泵的多图框选择集。
3. 1# 控制原理图复制为 2#、3# 并改号。
4. 外部接线图、端子排图和 PLC 图的图框归属。
5. 3 行 6 列板卡阵列重排。

### 11.4 性能与限制测试

- 200、1000、2000 个实体的详情读取、复制和变换。
- 大型建筑底图中的邻近查询，验证先包围盒预筛再精确计算。
- 大量文字的改号预览和提交耗时。
- 结果超过上限时必须明确返回截断或失败状态，禁止静默漏项。

## 12. 开发时容易出现的错误

1. **把图框当成最大矩形。** 实际图框更可靠的依据往往是块属性“图名”和块插入点。
2. **用实体包围盒中心代替真实几何距离。** 这会在 R4 圆弧和密集导线场景中选错对象。
3. **全局替换数字。** 泵编号变化不等于图中文字中的所有 `1` 都要变化。
4. **复制后重新创建文字。** 这容易丢失文字样式、对齐方式和块属性结构。
5. **查询结果被截断后继续写。** 整图复制和删除必须确认已取得完整实体集合。
6. **部分成功后提交。** 固定批量写工具必须保持事务原子性。
7. **调度器恢复了旧选择集。** `set_selection` 必须与现有选择快照机制协调。
8. **把匿名动态块名当作真实图框类型。** 应读取有效块名和属性标签。
9. **用遍历顺序解决歧义。** 候选相近时应返回歧义，而不是取数据库中的第一个对象。
10. **为单个行业场景过早开发专用大命令。** 第一、第二阶段应先完善通用原子能力。

## 13. 版本、兼容性与文档要求

- 不重命名或改变现有固定工具的行为。
- 新工具应加入设置界面的启用/禁用列表，并有中文说明。
- README 和 `docs/AUTOCAD_E2E_CHECKLIST.md` 应同步增加工具使用和人工验证步骤。
- 新工具增加是否构成 TCP 协议版本变化，需要结合实际传输契约单独评估；不能因为“增加了工具”就直接手工修改协议版本。
- `version.json` 是产品版本、TCP 协议版本和设置架构版本的唯一人工维护来源。
- 未取得用户给出的精确目标版本前，不得修改 `version.json`、运行 `scripts/set-version.ps1` 或改动派生版本。
- 如果新增工具导致设置架构确需变化，必须提供明确迁移逻辑和测试；版本修改仍需另行获得精确目标版本。
- 发生任何版本相关工作后必须运行 `scripts/test-version-consistency.ps1`。

## 14. 第一、第二阶段暂不包含的功能

以下能力与实际使用高度相关，但建议放到后续阶段：

- `compare_sheets`：比较 1#、2#、3# 图中的实体、编号和连接差异。
- `audit_electrical_connections`：检查重复线号、悬空导线、缺失触点和端子连接。
- `clone_sheet_with_mapping`：把图框识别、整图复制、编号映射和标题修改封装成一次受控操作。
- `detect_terminal_connections`：把端子、线号和导线拓扑结构化。
- `generate_terminal_schedule`：从图形连接关系生成端子表。
- `trace_plc_io`：追踪控制回路、端子排、外部接线与 PLC I/O 的对应关系。

这些功能依赖第一阶段的稳定编辑能力和第二阶段的范围/关系理解能力。先完成本计划，可显著降低后续行业功能的实现复杂度和误操作风险。

## 15. 总体验收定义

第一、第二阶段只有同时满足以下条件才算完成：

1. 11 个新工具均有严格的 MCP 参数模式、CommandSet 实现、设置开关和用户文档。
2. 所有写操作具备目标数量校验、原子事务、撤销边界和清晰错误码。
3. 复杂流程仍可与 `send_code_to_cad` 混合使用，不削弱动态代码能力。
4. 能不依赖临时 C# 完成两个 `R4` 圆弧的分析与选中。
5. 能不依赖临时 C# 完成一张泵控制图的识别、复制、移动、受控改号和图框属性修改。
6. 能准确拆分上下两排或左右多列图框，并取得每张图完整且不串图的实体集合。
7. 删除和批量修改在目标不确定时拒绝执行，不以“尽量完成”代替安全性。
8. Server 自动测试、纯逻辑测试和 AutoCAD 2022 人工端到端检查全部通过。

## 16. 优先级摘要

| 优先级 | 功能 | 原因 |
| --- | --- | --- |
| P0 | `get_entity_details` | 后续所有理解与修改的事实基础 |
| P0 | `set_selection` | 分析结果反馈到 CAD 的必要闭环 |
| P0 | `clone_entities` | 整图扩展任务中最频繁、最能保留样式的操作 |
| P0 | `replace_text` | 2#、3# 回路生成的核心改号能力 |
| P0 | `erase_entities` | 测试与返工时的安全保障 |
| P1 | `transform_entities` | 负责右侧、下方、阵列重排和对齐 |
| P1 | `set_block_attributes` | 图框标题和图号的精确修改 |
| P1 | `query_nearby_entities` | 为几何关系判断提供通用底层能力 |
| P1 | `detect_drawing_frames` | 多图选择集拆分的核心能力 |
| P1 | `get_sheet_entities` | 把图框识别结果转为可编辑实体集合 |
| P1 | `resolve_annotation_target` | 将 R4 等标注判断固化为可解释工具 |

建议严格按依赖关系开发，而不是同时铺开全部命令。最小可用增量是：`get_entity_details` + `set_selection`；第一个高价值编辑增量是：`clone_entities` + `replace_text` + `erase_entities`；第二阶段的完整价值增量是：`detect_drawing_frames` + `get_sheet_entities` + `query_nearby_entities` + `resolve_annotation_target`。
